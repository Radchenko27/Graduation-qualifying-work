# Выбор платформы и технологий

## Frontend: MVC архитектура с Jinja2 шаблонами

Разработка клиентской части системы осуществляется с использованием подхода Model-View-Controller (MVC) с серверным рендерингом шаблонов. Данный выбор обусловлен требованиями к быстрой разработке, простоте поддержки и возможности интеграции с существующей серверной частью на FastAPI.

Jinja2 был выбран в качестве шаблонизатора за счёт его гибкости, безопасности и широкой поддержки в экосистеме Python. «Jinja2 — это современный шаблонизатор для Python, который сочетает в себе простоту использования с мощными возможностями, такими как наследование шаблонов, фильтрация данных и автоматическое экранирование для защиты от XSS-атак» [1].

Одной из основных концепций работы с Jinja2 является разделение логики представления и бизнес-логики. Шаблоны отвечают исключительно за отображение данных, в то время как обработка запросов и работа с базой данных осуществляются на стороне сервера.

«Серверный рендеринг позволяет генерировать HTML-страницы на стороне сервера и отправлять уже полностью готовый контент клиенту. Это обеспечивает быструю загрузку страниц, лучшую SEO-оптимизацию и упрощает разработку по сравнению с клиентскими SPA-приложениями» [2].

Данный подход имеет как преимущества, так и недостатки. К преимуществам можно отнести простоту отладки, отсутствие необходимости в отдельном фронтенд-фреймворке, быструю первоначальную загрузку страниц и улучшенную работу с поисковыми системами. Недостатком является меньшая интерактивность по сравнению с клиентскими приложениями, однако для системы управления технической документацией это не является критичным требованием.

Для реализации интерактивных элементов (поиск, фильтрация, AJAX-запросы) используется нативный JavaScript с fetch API. Это позволяет избежать дополнительных зависимостей и сохранить лёгкость клиентской части.

## Backend: FastAPI и асинхронная архитектура

Для разработки серверной части системы был выбран фреймворк FastAPI. FastAPI — это современный, высокопроизводительный веб-фреймворк для создания API на Python 3.8+, основанный на типизации данных через Pydantic.

«FastAPI сочетает в себе простоту разработки на Python с производительностью, близкой к NodeJS и Go, благодаря использованию асинхронного программирования на основе asyncio и Starlette» [4].

Среди ключевых преимуществ FastAPI можно выделить:
- **Высокая производительность** — благодаря асинхронной природе и работе на основе ASGI (Uvicorn)
- **Автоматическая документация** — генерация OpenAPI и Swagger UI «из коробки»
- **Валидация данных** — интеграция с Pydantic для проверки типов и форматов данных
- **Зависимости (Dependency Injection)** — встроенная система управления зависимостями для аутентификации, работы с БД и других общих задач
- **Типобезопасность** — использование type hints для предотвращения ошибок на этапе разработки

Проект реализован в виде модульной монолитной архитектуры с разделением на логические компоненты. Такой подход обеспечивает баланс между простотой развёртывания и масштабируемостью. Проектная структура включает:

```
app/
├── routers/         # HTTP обработчики (контроллеры)
├── models/          # Модели данных (ORM)
├── schemas/         # Pydantic схемы валидации
├── crud/            # Операции с базой данных
├── dependencies/    # Зависимости (авторизация, сессии)
└── utils/           # Утилиты (парсинг PDF, экспорт)
```

Вся логика построена вокруг RESTful API с использованием JSON для обмена данными. Для аутентификации используется session-based подход с хранением сессий в базе данных и передачей через HTTP-only cookie. Это обеспечивает безопасность сессионных данных и защиту от XSS-атак.

«Аутентификация через cookie с флагом httponly защищает от кражи сессионных токенов через JavaScript и является рекомендуемым подходом для веб-приложений с серверным рендерингом» [5].

Для работы с асинхронными задачами и фоновыми процессами предусмотрена интеграция с Celery/RQ (в планах развития). Это позволит обрабатывать тяжёлые операции (парсинг PDF, генерация отчётов) без блокировки основного потока.

## Хранение файлов: MinIO объектное хранилище

Для хранения файлов технической документации (PDF, изображения, спецификации) используется MinIO — высокопроизводительное объектное хранилище, совместимое с Amazon S3 API.

MinIO был выбран благодаря следующим преимуществам:
- **Совместимость с S3** — возможность миграции на AWS S3 или другие совместимые решения без изменения кода
- **Высокая производительность** — оптимизирован для работы с большими файлами (PDF до 100 МБ)
- **Простота развёртывания** — запуск в виде Docker-контейнера без дополнительных зависимостей
- **Встроенное управление доступом** — токены доступа, политики безопасности, версионирование объектов
- **Открытый исходный код** — возможность модификации и самохостинга

Все файлы загружаются через backend-сервисы, где для каждого объекта создаётся уникальная ссылка с временным токеном доступа. Это позволяет безопасно управлять доступом к документам и исключить возможность несанкционированного скачивания.

«Объектные хранилища, такие как MinIO, предназначены для хранения неструктурированных данных (файлов, изображений, видео) и обеспечивают высокую доступность, масштабируемость и отказоустойчивость за счёт репликации данных» [6].

## Выбор СУБД

В качестве системы управления базами данных в проекте используется PostgreSQL — надёжная, масштабируемая и широко распространённая объектно-реляционная СУБД.

Выбор PostgreSQL обусловлен следующими факторами:

**1. Поддержка расширенного SQL** — PostgreSQL реализует большинство стандартов SQL, включая сложные запросы, оконные функции, Common Table Expressions (CTE), что позволяет эффективно работать со сложными связями между сущностями (проекты, пользователи, документы, сметы).

**2. Высокая производительность** — оптимизация запросов, индексы (B-Tree, GiST, GIN), партиционирование таблиц обеспечивают быструю работу даже при большом объёме данных.

**3. Надёжность и ACID-транзакции** — PostgreSQL гарантирует целостность данных при любых сбоях, что критично для финансовой информации (сметы, расчёты).

**4. Совместимость с ORM** — полная поддержка SQLAlchemy и Alembic для миграций, что упрощает разработку и поддерживает схему базы данных в актуальном состоянии.

**5. Расширяемость** — поддержка пользовательских типов данных, функций на PL/pgSQL, триггеров, внешних ключей.

PostgreSQL отлично подходит для хранения всех ключевых сущностей проекта:
- **users** — пользователи системы с ролевой моделью
- **projects** — строительные проекты с метаданными
- **documents** — техническая документация (PDF, спецификации)
- **drawings** — чертежи с привязкой к страницам
- **materials** — материалы и оборудование
- **drawing_calculations** — расчёты элементов чертежей
- **estimates** — сметы и их элементы

Также база данных поддерживает работу с массивами, JSONB-полями, что позволяет хранить гибкую структуру данных (метаданные документов, параметры материалов) без нарушения нормализации.

«PostgreSQL часто выбирается для enterprise-приложений благодаря своей надёжности, зрелости и активному сообществу. Она превосходит многие альтернативы в тестах на корректность транзакций и восстановление после сбоев» [7].

Для управления схемой базы данных используется Alembic — инструмент миграций для SQLAlchemy. Это позволяет версионировать структуру БД, применять изменения последовательно и откатывать при необходимости.

## Интеграция компонентов

Все компоненты системы взаимодействуют через чётко определённые интерфейсы:

```
┌─────────────────────────────────────────────────────────────┐
│                      КЛИЕНТ (Браузер)                       │
│         Jinja2 шаблоны + JavaScript (AJAX/Fetch)            │
└──────────────────────────┬──────────────────────────────────┘
                           │ HTTP/HTTPS
                           │ (REST API + Cookie)
                           ▼
┌─────────────────────────────────────────────────────────────┐
│                    FASTAPI SERVER                            │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────────────┐  │
│  │   Routers   │──│   CRUD      │──│   Dependencies      │  │
│  │  (Handlers) │  │  (Business) │  │  (Auth, DB Session) │  │
│  └─────────────┘  └─────────────┘  └─────────────────────┘  │
│         │                  │                    │            │
│         ▼                  ▼                    ▼            │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────────────┐  │
│  │   Models    │  │  Schemas    │  │      Utils          │  │
│  │   (ORM)     │  │ (Pydantic)  │  │  (PDF Parser)       │  │
│  └─────────────┘  └─────────────┘  └─────────────────────┘  │
└──────────┬──────────────┬───────────────────────┬───────────┘
           │              │                       │
           ▼              ▼                       ▼
┌─────────────────┐ ┌─────────────────┐ ┌─────────────────────┐
│   PostgreSQL    │ │     MinIO       │ │   Docker Containers │
│   (Данные)      │ │   (Файлы)       │ │   (Инфраструктура)  │
└─────────────────┘ └─────────────────┘ └─────────────────────┘
```

## Сравнение с альтернативами

| Технология | Альтернатива | Причина выбора |
|------------|--------------|----------------|
| **FastAPI** | Django, Flask | Асинхронность, автоматическая документация, скорость |
| **Jinja2** | React, Vue | Быстрая разработка, SEO, простота для MVC |
| **PostgreSQL** | MySQL, SQLite | Расширенный SQL, надёжность, поддержка JSONB |
| **MinIO** | AWS S3, локальное хранилище | Self-hosted, совместимость S3, контроль данных |
| **SQLAlchemy** | Django ORM, Pony ORM | Гибкость, поддержка асинхронности, зрелость |

## Выводы

Таким образом, выбор FastAPI, Jinja2, PostgreSQL и MinIO обусловлен требованиями к производительности, масштабируемости, безопасности и скорости разработки. Применение модульной архитектуры с разделением на логические компоненты позволило построить гибкую, легко сопровождаемую и расширяемую платформу для работы с технической строительной документацией.

Асинхронная природа FastAPI обеспечивает высокую производительность при работе с большим количеством одновременных запросов. PostgreSQL гарантирует целостность и надёжность хранения данных. MinIO предоставляет масштабируемое и безопасное хранилище для файлов. Все компоненты интегрированы через чётко определённые интерфейсы, что упрощает тестирование, развёртывание и дальнейшую разработку.

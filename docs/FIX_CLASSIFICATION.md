# Исправление классификации - Руководство

## Почему модель определяла всё как "схема"

### Причина
Старая модель обучалась на **оценках rule-based классификатора** (score_drawing, score_specification и т.д.).

**Проблема:** Если rule-based ошибался, ML выучила неверные паттерны.

```
Старые признаки для обучения:
  score_drawing: 5        ← оценка rule-based (может быть неверной!)
  score_specification: 0  ← оценка rule-based
  text_length: 525
```

**Результат:** Модель училась на "мусоре" → предсказывала "мусор"

---

## Что изменилось (улучшение v2)

### 1. Парсинг основной надписи (штампа)

**Где искать:** Правый нижний угол страницы (по ГОСТ)

**Что извлекаем:**
- "Чертеж" / "Схема" / "Спецификация" / "Ведомость"
- Тип документа из штампа

**Вес:** +10 баллов (очень высокий) — штамп не врёт!

### 2. Объективные текстовые признаки

**Используем реальные ключевые слова из текста:**
- "чертеж", "план", "разрез", "КЖ", "КМ" → drawing
- "спецификация", "ведомость", "позиция" → specification
- "схема", "блок-схема", "принципиальная" → scheme

**НЕ используем:** оценки rule-based (score_*)

### 3. Структурные признаки

- Чертёжное обозначение (ГОСТ 2.201) → drawing
- Таблицы + много текста → specification
- Подписи "Утверждаю", "Разработал" → title

## Признаки, используемые сейчас

| Признак | Источник | Вес |
|---------|----------|-----|
| **stamp_drawing** | Основная надпись | +10 |
| **stamp_specification** | Основная надпись | +10 |
| **stamp_scheme** | Основная надпись | +10 |
| **kw_drawing** | Ключевые слова в тексте | +2 каждое |
| **kw_specification** | Ключевые слова в тексте | +2 каждое |
| **kw_scheme** | Ключевые слова в тексте | +2 каждое |
| **has_drawing_number** | Чертёжное обозначение | +3 |
| **has_table** | Таблицы на странице | +4 |
| **has_signatures** | Подписи | +5 (для title) |
| **images** | Количество изображений | +2 если ≥2 |

**Убрано:** score_drawing, score_specification, score_scheme (оценки rule-based)

## Как исправить (пошагово)

### Шаг 1: Пересоздать document_pages с новым классификатором

```powershell
python scripts/rebuild_pages_v2.py
```

**Что делает:**
1. Скачивает каждый PDF из MinIO
2. Парсит основную надпись (штамп)
3. Извлекает ключевые слова из текста
4. Классифицирует с улучшенным rule-based
5. Перезаписывает таблицу document_pages

**Введите `yes` для подтверждения.**

---

### Шаг 2: Проверить новую классификацию

```powershell
python scripts/view_pages.py
```

Посмотрите, правильно ли определились категории.

---

### Шаг 3: Обучить новую ML модель (на объективных признаках)

```powershell
python scripts/train_ml_classifier_v2.py
```

**Что нового:**
- Извлекает признаки напрямую из PDF (не из старого metadata)
- Не использует score_* от rule-based
- Использует только: штамп, ключевые слова, визуальные признаки

**Результат:** `models/ml_classifier_v2.pkl`

---

### Шаг 4: Перезапустить сервер

```powershell
# Остановить (Ctrl+C)
# Запустить заново:
uvicorn app.main:app --reload
```

---

### Шаг 5: Проверить на новом документе

Загрузите новый PDF через веб-интерфейс.

Классификация должна использовать:
1. ML модель (если загружена)
2. Улучшенный rule-based с парсингом штампа

## Если классификация всё ещё неверная

### Ручная корректировка

```powershell
# Исправить конкретную страницу
python scripts/fix_page_category.py --document 16 --page 3 --category drawing
```

### Переобучить модель после ручной правки

```powershell
python scripts/train_ml_classifier_v2.py
```

## Требования для хорошей модели

| Требование | Минимум | Оптимум |
|-----------|---------|---------|
| Разных документов | 3+ | 10+ |
| Всего страниц | 50 | 200+ |
| Категория "drawing" | 15+ | 50+ |
| Категория "specification" | 15+ | 50+ |
| Категория "scheme" | 5+ | 20+ |
| Категория "title" | 5+ | 20+ |

**У вас сейчас:** 1 документ, 99 страниц — мало для хорошей ML модели!

**Рекомендация:** Загрузите больше разных PDF (чертёжные документы, схемы, спецификации) и пересоздайте данные.

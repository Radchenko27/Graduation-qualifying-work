# Классификация документов

## Категории документов

Система использует фиксированный список категорий для классификации документов:

| Категория | Описание | Использование |
|-----------|----------|---------------|
| `project_documentation` | Проектная документация | Общие документы проекта, ТЗ, планы |
| `working_drawings` | Рабочие чертежи | Чертежи, схемы, планы для строительства |
| `specifications` | Спецификации | Ведомости оборудования, материалов |
| `calculations` | Расчёты | Инженерные расчёты, обоснования |
| `permits` | Разрешительная документация | Согласования, разрешения, лицензии |
| `other` | Другое | Документы, не вошедшие в другие категории |

## Структура связей

```
Проект
  └── Документ (с категорией)
        ├── Чертежи (привязаны к документу)
        │     └── Расчёты элементов
        │           └── Элементы сметы
        │
        └── Материалы (привязаны к чертежам)
              └── Отчёты (сводные данные)
```

## Как работает

### 1. Создание документа

При загрузке документа **обязательно** указывается категория:

```
POST /api/documents/
{
  "project_id": 1,
  "name": "Чертежи фундамента",
  "category": "working_drawings",  // Обязательно!
  "file": <PDF файл>
}
```

### 2. Привязка чертежей

Чертежи создаются **внутри документа**:

```
POST /api/drawings/
{
  "document_id": 5,      // Ссылка на документ
  "project_id": 1,
  "number": "АБВГ.12345.001",
  "name": "Фундамент",
  "type": "Конструктивные решения",
  "scale": "1:100",
  "area": 150.5
}
```

### 3. Расчёты элементов

Расчёты привязываются к чертежам:

```
POST /api/drawing-calculations/
{
  "drawing_id": 10,
  "project_id": 1,
  "element_name": "Бетонная плита",
  "element_type": "concrete",
  "quantity": 25.5,
  "unit": "м³"
}
```

### 4. Сметы

Сметы формируются из расчётов:

```
POST /api/estimates/
{
  "project_id": 1,
  "name": "Смета на фундамент",
  "description": "Общая смета"
}

# Добавление элемента сметы
POST /api/estimate-items/
{
  "estimate_id": 3,
  "drawing_calculation_id": 15,
  "quantity": 1.0,
  "unit_cost": 50000.0
}
```

## Преимущества системы

1. **Чёткая иерархия** - документ → чертеж → расчёт → смета
2. **Контроль категорий** - все документы классифицированы
3. **Автоматические связи** - удаление документа удаляет все связанные данные
4. **Гибкость** - можно добавлять новые категории при необходимости

## Примеры использования

### Пример 1: Проект здания

```
Проект: "ЖК Солнечный"
├── Документ: "Проектная документация" (project_documentation)
├── Документ: "Чертежи фундамента" (working_drawings)
│   ├── Чертеж: "Фундаментная плита"
│   │   ├── Расчёт: "Арматура"
│   │   └── Расчёт: "Бетон"
│   └── Чертеж: "Арматурный каркас"
├── Документ: "Спецификация материалов" (specifications)
└── Смета: "Общая смета"
    ├── Элемент: "Бетон" (из расчётов)
    └── Элемент: "Арматура" (из расчётов)
```

### Пример 2: Разрешительная документация

```
Проект: "Реконструкция цеха"
├── Документ: "Разрешение на строительство" (permits)
├── Документ: "Технические условия" (permits)
└── Документ: "Акты скрытых работ" (other)
```

## API Endpoints

| Метод | Путь | Описание |
|-------|------|----------|
| `POST` | `/api/documents/` | Загрузить документ с категорией |
| `GET` | `/api/documents/?category=X` | Получить документы по категории |
| `POST` | `/api/drawings/` | Создать чертеж в документе |
| `GET` | `/api/drawings/?document_id=X` | Получить чертежи документа |
| `POST` | `/api/drawing-calculations/` | Добавить расчёт к чертежу |
| `POST` | `/api/estimates/` | Создать смету проекта |

## Важные замечания

1. **Категория обязательна** - документ без категории создать нельзя
2. **Нельзя изменить категорию** - выбрал категорию, работай с ней
3. **Чертежи только в документах** - нельзя создать чертеж без документа
4. **Каскадное удаление** - удаление документа удаляет все чертежи и расчёты

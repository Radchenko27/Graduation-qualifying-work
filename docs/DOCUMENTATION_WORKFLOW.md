# Руководство по работе с документацией

## Обзор жизненного цикла документа

Данный документ описывает полный цикл обработки технической документации в системе — от загрузки файла до получения расчётов и смет.

---

## Этап 1: Загрузка документа

### Что делаем:
Загружаем PDF-файл технической документации в систему.

### Где:
- **UI:** Раздел "Документы" → кнопка "Загрузить документ"
- **API:** `POST /api/documents/`
- **Хранилище:** MinIO (объектное хранилище)

### Входные данные:
```
- Файл: PDF документ (спецификация, чертёж, смета)
- Метаданные:
  • project_id — ID проекта
  • name — название документа
  • doc_type — тип (спецификация/чертёж/смета)
  • file — бинарные данные PDF
```

### Процесс:
1. Пользователь выбирает файл через UI или отправляет через API
2. Система генерирует хеш файла (SHA-256) для проверки целостности
3. Файл загружается в MinIO в bucket `documents/{project_id}/`
4. Записывается метаданный в таблицу `documents`:
   - `file_path` — путь к файлу в MinIO
   - `file_hash` — хеш файла
   - `page_count` — количество страниц (получается при загрузке)

### Выходные данные:
```json
{
  "id": 1,
  "project_id": 1,
  "name": "03-23-ОГР01.1-ЭОМ1.1-Изм.1.pdf",
  "doc_type": "specification",
  "category": null,
  "file_path": "documents/1/03-23-ОГР01.1-ЭОМ1.1-Изм.1.pdf",
  "file_hash": "a3f2b8c9d1e4f5...",
  "page_count": 157,
  "created_at": "2025-01-15"
}
```

### Проверка:
```sql
SELECT * FROM documents WHERE id = 1;
-- Ожидаем: файл загружен, page_count = 157, file_hash заполнен
```

## Этап 2: Классификация документа

### Что делаем:
Назначаем документу категорию для последующей фильтрации и группировки.

### Где:
- **UI:** Редактирование документа → выпадающий список категорий
- **API:** `PUT /api/documents/{id}/category`

### Доступные категории:
| Категория | Описание | Пример |
|-----------|----------|--------|
| `specification` | Спецификация оборудования | Ведомость материалов |
| `drawing` | Чертеж | План освещения |
| `estimate` | Смета | Локальная смета |
| `explanatory_note` | Пояснительная записка | Общие данные |
| `change_log` | Изменения | Изм. №1, Изм. №2 |

### Входные данные:
```json
{
  "category": "specification"
}
```

### Процесс:
1. Пользователь выбирает категорию из списка
2. Система обновляет поле `documents.category`
3. Документ появляется в фильтрах по выбранной категории

### Выходные данные:
```json
{
  "id": 1,
  "category": "specification",
  "updated_at": "2025-01-15T10:30:00"
}
```

### Проверка:
```sql
SELECT id, name, category FROM documents WHERE id = 1;
-- Ожидаем: category = 'specification'
```

## Этап 3: Обработка документа (парсинг PDF)

### Что делаем:
Извлекаем текст из PDF для последующего анализа спецификаций.

### Где:
- **UI:** Кнопка "Обработать документ" (фоновая задача)
- **API:** `POST /api/documents/{id}/parse` (план)
- **Утилита:** `app/utils/pdf_parser.py`

### Процесс:
1. PDF файл извлекается из MinIO
2. Текст извлекается постранично (PyMuPDF или pdfplumber)
3. Каждая страница сохраняется в JSON:
   ```json
   {
     "metadata": {
       "file_name": "03-23-ОГР01.1-ЭОМ1.1-Изм.1.pdf",
       "page_count": 157,
       "created_at": "2025-01-15"
     },
     "text": {
       "0": "Текст страницы 0...",
       "1": "Текст страницы 1...",
       ...
     }
   }
   ```
4. JSON файл сохраняется в `processed/{document_name}/`

### Выходные данные:
```
processed/
└── 03-23-ОГР01.1-ЭОМ1.1-Изм.1/
    └── 03-23-ОГР01.1-ЭОМ1.1-Изм.1_processed.json (50 МБ)
```

### Проверка:
```bash
ls processed/03-23-ОГР01.1-ЭОМ1.1-Изм.1/
# Ожидаем: 03-23-ОГР01.1-ЭОМ1.1-Изм.1_processed.json
```

## Этап 4: Извлечение материалов и чертежей

### Что делаем:
Анализируем текст и извлекаем структурированные данные о материалах и чертежах.

### Где:
- **UI:** Раздел "Материалы" → импорт из JSON
- **API:** `POST /api/materials/import-from-json`
- **Утилита:** `PDFDataExtractor.extract_specifications()`

### Процесс:
1. Загружаем обработанный JSON файл
2. Сканируем текст постранично
3. Ищем страницы со спецификациями (ключевые слова: "спецификация", "ведомость")
4. Парсим строки по паттернам:
   - **Кабели:** `ПРГнг(А)-HF 3×2,5`
   - **Светильники:** `светильник светодиодный`
   - **Устройства:** `розетка`, `выключатель`, `датчик`
5. Извлекаем:
   - Название материала
   - Марку/артикул
   - Количество
   - Единицу измерения
   - Номер страницы

### Выходные данные:
```json
[
  {
    "type": "cable",
    "name": "ППГнг(А)-HF 3×2,5",
    "mark": "ППГнг(А)-HF 3×2,5",
    "quantity": 150,
    "unit": "м",
    "page_number": 5,
    "source_file": "03-23-ОГР01.1-ЭОМ1.1-Изм.1_processed.json"
  },
  {
    "type": "device",
    "name": "Розетка 16А",
    "mark": "",
    "quantity": 200,
    "unit": "шт",
    "page_number": 10
  }
]
```

### Проверка:
```sql
SELECT COUNT(*) FROM materials;
-- Ожидаем: 150+ материалов

SELECT type, COUNT(*) FROM materials GROUP BY type;
-- Ожидаем: cable: 45, device: 30, fixture: 25, general: 50
```

## Этап 5: Создание расчётов элементов чертежа

### Что делаем:
Создаём расчёты для выбранных элементов из спецификации.

### Где:
- **UI:** Раздел "Чертежи" → выбор элемента → форма расчёта
- **API:** `POST /api/drawing-calculations/`

### Входные данные:
```json
{
  "drawing_id": 1,
  "project_id": 1,
  "element_name": "Кабель ППГнг(А)-HF 3×2,5 для розеточной сети",
  "element_type": "cable",
  "quantity": 150,
  "unit": "м",
  "calculation_result": "150 м = 120 м (основная трасса) + 30 м (запас 25%)"
}
```

### Процесс:
1. Пользователь выбирает чертёж (через `drawings.page_number`)
2. Выбирает элементы из спецификации
3. Вводит параметры расчёта (количество, формула)
4. Система создаёт запись в `drawing_calculations`

### Выходные данные:
```json
{
  "id": 1,
  "drawing_id": 1,
  "project_id": 1,
  "element_name": "Кабель ППГнг(А)-HF 3×2,5",
  "element_type": "cable",
  "quantity": 150,
  "unit": "м",
  "calculation_result": "150 м = 120 м + 30 м (запас)",
  "created_at": "2025-01-15T11:00:00"
}
```

### Проверка:
```sql
SELECT id, element_name, quantity, unit FROM drawing_calculations;
-- Ожидаем: расчёты созданы с корректными значениями
```

## Этап 6: Объединение расчётов в сметы

### Что делаем:
Объединяем несколько расчётов в одну смету.

### Где:
- **UI:** Раздел "Сметы" → выбрать расчёты → кнопка "Объединить"
- **API:** `POST /api/estimates/merge`

### Входные данные:
```json
{
  "name": "Смета на электромонтаж",
  "description": "Объединённая смета по всем расчётам",
  "estimate_ids": [1, 2, 3]
}
```

### Процесс:
1. Пользователь выбирает несколько смет (или расчётов)
2. Система создаёт новую смету
3. Переносит все элементы (`estimate_items`) из выбранных смет
4. Пересчитывает итоговые суммы:
   - `total_quantity` = Σ(quantity)
   - `total_cost` = Σ(quantity × unit_cost)

### Выходные данные:
```json
{
  "id": 5,
  "project_id": 1,
  "name": "Смета на электромонтаж",
  "description": "Объединённая смета по всем расчётам",
  "total_cost": 125000.50,
  "total_quantity": 1250,
  "created_at": "2025-01-15T12:00:00",
  "updated_at": "2025-01-15T12:00:00",
  "items": [
    {"element_name": "Кабель ППГнг(А)-HF 3×2,5", "quantity": 150, "total_cost": 7500},
    {"element_name": "Розетка 16А", "quantity": 200, "total_cost": 10000},
    ...
  ]
}
```

### Проверка:
```sql
SELECT e.name, e.total_cost, COUNT(i.id) as items_count
FROM estimates e
JOIN estimate_items i ON e.id = i.estimate_id
WHERE e.id = 5
GROUP BY e.id;
-- Ожидаем: смета с корректной итоговой суммой
```

## Этап 7: Формирование отчёта и экспорт

### Что делаем:
Генерируем итоговый отчёт и экспортируем в PDF/Excel.

### Где:
- **UI:** Раздел "Сметы" → кнопка "Экспорт" → выбор формата
- **API:** `GET /api/reports/{id}/export?format=pdf`

### Процесс:
1. Пользователь выбирает смету для экспорта
2. Система формирует отчёт:
   - Заголовок с метаданными проекта
   - Таблица материалов с количеством и стоимостью
   - Итоговые суммы
3. Генерирует PDF/Excel файл
4. Сохраняет в MinIO или отдаёт на скачивание

### Выходные данные:
```
СМЕТА НА ЭЛЕКТРОМОНТАЖ
Проект: Комплекс жилых домов, г. Москва, Огородный проезд

┌──────────────────────────────────────────────────────────────┐
│ Материал                │ Марка            │ Кол-во │ Сумма  │
├──────────────────────────────────────────────────────────────┤
│ Кабель                  │ ППГнг(А)-HF 3×2,5│ 150 м  │ 7 500  │
│ Розетка                 │ 16А              │ 200 шт │ 10 000 │
│ Светильник              │ светодиодный     │ 80 шт  │ 40 000 │
├──────────────────────────────────────────────────────────────┤
│ ИТОГО:                                        │ 57 500 │
└──────────────────────────────────────────────────────────────┘
```

### Проверка:
```bash
# Файл экспорта
ls exports/
# Ожидаем: estimate_5_2025-01-15.pdf
```

## Пример полного рабочего процесса

### Сценарий: Подготовка сметы для проекта "Комплекс жилых домов"

```
1. Создаём проект
   POST /api/projects/
   → project_id = 1

2. Загружаем спецификацию (PDF 157 страниц)
   POST /api/documents/
   → document_id = 1, file_path = "documents/1/spec.pdf"

3. Назначаем категорию
   PUT /api/documents/1/category
   → category = "specification"

4. Обрабатываем PDF (фоновая задача)
   python -m app.utils.pdf_parser processed/spec_processed.json
   → processed/spec_processed.json (50 МБ)

5. Извлекаем материалы
   POST /api/materials/import-from-json
   → 150 материалов в БД

6. Создаём расчёты для 10 элементов
   POST /api/drawing-calculations/ (10 раз)
   → 10 записей в drawing_calculations

7. Создаём 3 промежуточные сметы
   POST /api/estimates/ (3 раза)
   → estimate_id = 1, 2, 3

8. Объединяем сметы
   POST /api/estimates/merge
   → final_estimate_id = 4, total_cost = 125 000 ₽

9. Экспортируем в PDF
   GET /api/reports/4/export?format=pdf
   → exports/estimate_4_2025-01-15.pdf
```

## Возможные проблемы и решения

| Проблема | Причина | Решение |
|----------|---------|---------|
| Файл не загружается | Превышен размер лимита | Увеличить `MAX_CONTENT_LENGTH` в FastAPI |
| Парсинг не находит материалы | Паттерны не совпадают | Добавить новые regex в `pdf_parser.py` |
| Материалы дублируются | Одинаковые name + mark | Проверять существование перед вставкой |
| Смета считает неверно | price = 0 | Установить цену для материалов |
| PDF не открывается | Файл повреждён | Проверить hash, перезагрузить |

## API Endpoints для работы с документацией

| Метод | Endpoint | Описание |
|-------|----------|----------|
| **Документы** |
| POST | `/api/documents/` | Загрузить документ |
| GET | `/api/documents/` | Список документов |
| GET | `/api/documents/{id}` | Детали документа |
| PUT | `/api/documents/{id}/category` | Обновить категорию |
| DELETE | `/api/documents/{id}` | Удалить документ |
| **Материалы** |
| POST | `/api/materials/import-from-json` | Импорт из JSON |
| GET | `/api/materials/search?q=` | Поиск материалов |
| **Чертежи** |
| POST | `/api/drawings/` | Создать чертёж |
| GET | `/api/drawings/?page_number=` | Фильтр по странице |
| **Расчёты** |
| POST | `/api/drawing-calculations/` | Создать расчёт |
| GET | `/api/drawing-calculations/?drawing_id=` | Расчёты чертежа |
| **Сметы** |
| POST | `/api/estimates/` | Создать смету |
| POST | `/api/estimates/merge` | Объединить сметы |
| GET | `/api/estimates/{id}` | Детали сметы |

## Заключение

Данный процесс обеспечивает полный контроль над технической документацией — от загрузки исходного PDF до формирования итоговой сметы. Каждая стадия имеет чёткие входные и выходные данные, что позволяет отслеживать состояние документа и при необходимости откатывать изменения.
